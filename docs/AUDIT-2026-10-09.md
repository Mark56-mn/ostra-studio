## B. Gaps against the request, in the spec's own dependency order

Severity: **BLOCKER** = the primary outcome is impossible without it; **GAP** = required by the spec;
**DEFECT** = advertised but untrue.

1. **BLOCKER — No season entity and no season-first approval gate (spec §5).** Approvals exist only per
   *episode* (`approvals.episode_id` is `NOT NULL` in `001_initial.sql`). There is no season package to
   approve, and nothing prevents production tasks from being created before any story is approved. The
   spec's acceptance test *"No downstream production starts before the required story approval"* cannot
   pass today.
2. **BLOCKER — No image generation (spec §3C).** `Image AI` exists only as a `ColabImageRuntimeStarter`
   returning `NOT_AUTOSTARTABLE`; no model endpoint is wired. `IMPLEMENTATION_PLAN.md` Phase 5: "interface
   shipped".
3. **BLOCKER — No image-to-video (spec §3D).** No code path exists at all.
4. **BLOCKER — No TTS/narration (spec §3E).** Kokoro-82M is the declared initial target
   (`CONSTRAINTS.md` 9) but nothing calls any TTS engine.
5. **BLOCKER — No video assembly (spec §3F).** `IMPLEMENTATION_PLAN.md` Phase 7: "not started". No FFmpeg
   invocation anywhere in `apps/` or `packages/`.
6. **GAP — No notifications (spec §8).** No table, no route, no UI. The spec requires in-app
   notifications first.
7. **GAP — No object-storage upload path (spec §8).** `artifacts.storage_path` documents a Supabase
   Storage bucket `ostra-assets`, but no code uploads to it; `createArtifact` writes metadata only.
8. **GAP — No production dispatcher (spec §7).** Tasks carry `depends_on`, but nothing walks the
   dependency graph and dispatches ready work to online workers. Today every task is created by hand.
9. **GAP — YouTube is an offline stub (`IMPLEMENTATION_PLAN.md` Phase 9).**
10. **DEFECT (fixed earlier, still open on the ops side) — CORS allowlist.** `packages/shared/src/lib/cors.ts`
    refuses unknown origins with a real 403 (verified 2026-10-09: preview origin → `CORS blocked`; the
    Vercel origin → 204). `CORS_ORIGINS` must be set on Render for the dashboard to call the API from a
    browser. Server-side calls are unaffected.

## C. What was verified live (2026-10-09)

- Backend `https://ostra-studio-1.onrender.com/api/health` → 200, Supabase ONLINE.
- CORS behaviour above, measured with real preflights.
- **NVIDIA free-tier research (verified against NVIDIA's own pages, not memory):**
  - **Image + image-to-video:** `nvidia/cosmos3-nano` is the *only* visual model with a verified free
    hosted endpoint. One route for both modes:
    `POST https://ai.api.nvidia.com/v1/cosmos/nvidia/cosmos3-nano`, `model_mode: "text2image"` →
    `b64_image` (JPEG); `model_mode: "image2video"` with `input_reference` (data URI or URL) →
    `b64_video` (VP9 in MP4). Resolutions `256p|480p|720p` with aspect suffix; ≤197 frames at 720p
    (~8.2 s at 24 fps), ≤397 at 256p. Synchronous POST; NVIDIA publishes no fixed quota or latency.
    Sources: build.nvidia.com model card + system card.
  - **Not verified free, therefore not integrated:** `black-forest-labs/flux.1-schnell` (Aug 2026 forum
    reports of `403` on the hosted route), `bytedance/seedance-1-pro`, `wan2.1`, `ltx-video`, `mochi`
    (no free hosted endpoint found).
  - **TTS:** `nvidia/magpie-tts-multilingual` has a documented hosted HTTPS route
    `POST …invocation.api.nvcf.nvidia.com/v1/audio/synthesize` (multipart: `text`, `language`, `voice`,
    optional `encoding`/`sample_rate_hz`), 2,000-character input limit, trial terms (throttling allowed).
    Self-hosted **Kokoro-82M** (Apache-2.0 weights, 24 kHz WAV, per-character voice selection) remains
    the repo's declared target and needs no API quota.

**Conclusion (spec §6, stated as the limitation it is):** text-to-speech is available and wired today.
Image generation and image-to-video are **not available through this account's NVIDIA tier right now**
— the routes answer 404, which means "not enabled for this account", not "bad key" (the same host
returns proper 400s for malformed requests). The adapters are built and wired so that enabling a
visual model on build.nvidia.com makes the pipeline work with **no code change**; until then every
call reports the real 404 rather than fabricating an asset.
