## 8. Decisions
- **Alias-not-replace for env vars** — `SUPABASE_CONNECTION_STRING` and `WORKER_REGISTRATION_SECRET` remain aliases (`getSupabaseUrl()` checks `SUPABASE_URL ?? SUPABASE_CONNECTION_STRING ?? NEXT_PUBLIC_SUPABASE_URL`; `expectedRegistrationToken()` checks `WORKER_REGISTRATION_TOKEN ?? WORKER_REGISTRATION_SECRET`). `GOOGLE_CLOUD_PROJECT/COLAB_PROJECT_ID/GCP_PROJECT_ID/GOOGLE_PROJECT_ID`, `GOOGLE_OAUTH_TOKEN/COLAB_OAUTH_TOKEN/COLAB_ACCESS_TOKEN/GOOGLE_ACCESS_TOKEN`, and `COLAB_RUNTIME_SPEC`/`COLAB_MACHINE_SHAPE` are similarly aliases — per `Constraints` #23 ("do not rebuild working systems without a documented reason") and to keep `docs/ENV.md` explicit while preserving backward compat.
- **Real Kaggle push replaces synthetic probe** — previously `GET /kernels/list?mine=true` then `provider_run_id = kernelRef#startup_request_id` (fabricated); now `resolveKaggleKernelRef` resolves `notebook7eae283a4a` → `owner/slug` via API `search=` before `verify` → `fetch kernel source` → `POST kernels/push` `ApiSaveKernelRequest` → `ref@vN` (real `versionNumber`/`url`/`ref`). Never concatenates `startup_request_id` into `provider_run_id`; `startup_request_id` is our correlation only.
- **Persisted lease over in-memory mutex** — `runtime_startup_leases` row + `expires_at` + partial unique `one_active where released_at is null` + expiry sweep before acquire, TTL `max(cooldown,30)m`, released after `REQUESTED→STARTING` — worker health (`ONLINE`) is the arbiter, not the lease. Survives Render restart. Duplicate protection still `healthy? → lease? → cooldown/maxAttempts` in `scheduler.ts` before any fetch.
- **startup_request_id is a correlation id, not unique** — fixed `003` to drop the unique `WHERE startup_request_id IS NOT NULL`; plain `idx_runtime_startup_history_startup_request_id` is intentional so `REQUESTED`+`STARTING` share the same `req:` or `kaggle:` id.
- **Colab `autostartable=true` but truthful at `start()`** — previous `autostartable=false` silently skipped the scheduler entirely, hiding concrete blockers (`missing_project`/`missing_token`/`allowlist`/`bootstrap_not_configured`). Now `schedulerTick` can call the starter, which returns `NOT_AUTOSTARTABLE`/`AUTH_FAILED` with `reason` in `provider_response` → scheduler writes `CANCELLED`/`FAILED` history with `error_code` and `scheduler.skipped_not_autostartable`/`start_failed` events — truthful and auditable, matching `Constraints` #4 ("No Mock Mode — STATUS=OFFLINE/WAITING/FAILED when unavailable; UI tells the truth") and `tsk` §5 (real-service first).
- **Notebook URL is not execution** — `COLAB_NOTEBOOK_URL` present but no `COLAB_*_BOOTSTRAP_URL` → `NOT_AUTOSTARTABLE` with `notebook URL alone is not an execution method`; the swarm "replace Startup Mode with a read-only Resource URL" idea is rejected per review feedback — `startup_mode` is what the supervisor uses to decide to start (not to display), and a link is not a trigger.
- **Secrets always redacted** — `redactSecrets()` now scrubs `KAGGLE_API_TOKEN`, `token`, `api_token`, `access_token`, `oauth_token`, `service_account`, `private_key` + long `KGAT_/ya29./1//…/eyJ` values in every `provider_response`/`events.payload` before persisting or logging; no secret flows to Vercel.
- **Timezone in the row, UTC math via `Intl` only** — no heavy tz lib on the API; keeps Render image small; handles `Africa/Lagos` (+01:00) and DST-observing zones.
- **Three daily windows are data, not code** — `Morning 09:00/Afternoon 14:00/Evening 20:00 Africa/Lagos` live only in seeded `runtime_schedules`; `PATCH local_time` respected on next tick (Case F) because tick reads DB each minute.
- **Run Now = same `evaluateAndStart`** — `runNow(supa,id)` shares the exact path (healthy/lease/cooldown/maxAttempts); `runNowByWorker` bypasses cooldown for ad-hoc with TTL 30; `startup_mode=not_autostartable` is still skipped even on `run_now` (recorded `CANCELLED`/`NOT_AUTOSTARTABLE`).
